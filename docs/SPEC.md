# 新潟市中央卸売市場 月報バーチャートレース 仕様書

Claude Code 向けの実装仕様。データ構造は 2023年1月分と 2026年8月分の実CSVで確認済み（2026-10-15 時点）。確認していない事項は「未確認」と明記している。

> P0 の調査で判明した事項（花き部の開始月、元データの不具合など）は [HANDOVER.md](HANDOVER.md) を参照。本書は元の仕様のまま保管している。

## 1. ゴール

新潟市中央卸売市場の月報オープンデータから、品目別・産地別の取扱量の月次推移を「順位が入れ替わる棒グラフ（バーチャートレース）」で見せる静的Webサイトを作る。実用性より「見ていて面白い」ことを優先する。スマホで見ることを前提にする（モバイルファースト）。

## 2. スコープ

### MVP に含める
- 全月（2023年1月〜最新月、2026年8月時点で44か月）のCSV取得・整形
- 品目別／産地別のバーチャートレース
- 大品目の切り替え、再生・一時停止・月スライダー、速度変更
- 現在の年月を大きく表示
- 出来事の自動キャプション
- CC-BY のクレジット表示
- 月次の自動更新

### MVP に含めない（将来拡張）
- 品目クリックでの順位推移（バンプチャート）
- 単価の推移（`T08`/`R08`/`V08` の主要品目数量・平均単価対比表を使う）
- 日別取扱高（`09`）、県内・県外対比（`10`）
- 年報（2022〜2025年の4年分のみ。月次推移には使えない）
- D3.js への移行（ECharts で足りない演出が出た場合のみ）

## 3. データソース

### 3.1 入口
- 月報一覧ページ: `https://www.city.niigata.lg.jp/shisei/seisaku/it/open-data/opendata-keizai/od-ichibageppou/index.html`
- 一覧に「YYYY年M月分 中央卸売市場月報」のリンクが月ごとにある。2026年8月時点で 2023年1月〜2026年8月の44件。
- ライセンス: CC-BY 2.1 日本。更新頻度は毎月（公開は月の中旬。2023年1月分は2/14、2026年8月分は9/17）。

### 3.2 使うCSV（各月ページの「各種データ」にある）
部門ごとに、次の2種類だけを使う。

| 部門 | コード | 品目別順位表（リンク文言） | 産地別順位表（リンク文言） |
|---|---|---|---|
| 青果部 | R | 品目別取扱高順位表 (`R11`) | 産地別取扱高順位表 (`R12`) |
| 水産物部 | T | 同上 (`T11`) | 同上 (`T12`) |
| 花き部 | V | 同上 (`V11`) | 同上 (`V12`) |

### 3.3 URL・ファイル名は不規則（必ずページからリンクを取得すること）
- **月ページのURLは月から推測できない。** 例:
  - 2024年11月分 → `ichiba202412geppou.html`（名前は 202412 だが11月分）
  - 2024年8月分 → `odichiba20240904.html`
  - 2026年8月分 → `odichibagepou202608.html`（`gepou` と綴りが違う）
  - 年月は URL ではなく、一覧のリンク文言（「2024年11月分」）または CSV 内の `年［西暦］`・`月` 列から取る。
- **CSVのファイル名も年代で違う。**
  - 2023年1月分: `od-202301T11-hinmokubetsutoriatsukai.csv`
  - 2026年8月分: `202608_T11.csv`
  - 格納先フォルダは `{月ページ名}.files/`
  - 識別は、リンク文言（「品目別取扱高順位表」「産地別取扱高順位表」）と、見出し（青果部／水産物部／花き部）を主キーにする。ファイル名の正規表現 `(\d{6})_?([RTV])(\d{2})` は照合用の副次チェックにとどめる。
- 2023年1月分のページ補足には「青果部及び水産物部」とあり、**花き部は無い**。花き部が始まる月は未確認なので、取得時に検出して記録する（花き部が無い月はエラーにしない）。

## 4. CSV の構造（確認済み）

### 4.1 品目別順位表（`R11`/`T11`/`V11`）
ヘッダー: `大品目,年［西暦］,月,品目,順位,数量合計［単位］,数量合計比率［％］,金額合計［円］,金額合計比率［％］,主要産地`

### 4.2 産地別順位表（`R12`/`T12`/`V12`）
ヘッダー: `大品目,年［西暦］,月,順位,原産地,数量合計［単位］,数量合計比率［％］,金額合計［円］,金額合計比率［％］,主要品目`

2023年1月分と2026年8月分でヘッダーは同一。

### 4.3 大品目
- 水産: 生鮮水産物／冷凍水産物／塩干・加工品その他
- 青果: 野菜／果実
- 花き: 切花類／鉢物類
- 1ファイルに複数の大品目が縦に並ぶ。各大品目は順位1〜20の20行の後に「その他」行が1行付く。

### 4.4 パースで注意する点
1. **「その他」行**は先頭列（大品目・年・月、産地表では順位も）が空欄。直前の行の大品目に紐づけ、年月はファイルの値を補う。順位は付けない。通常のランキングには含めず、検算用に別保持する。
2. **順位は数量（kg）の降順。** 順位表の上位20位は数量で選ばれている。金額順ではない（金額は順不同）。
3. **数量の単位は列名に入っている。** 水産・青果は `［㎏］`、花き部は `［本/鉢］`。列名を正規表現（`数量合計［(.+)］`）で読み、単位を保持する。大品目をまたいで数量を比較しない。
4. **「主要産地」「主要品目」の区切り文字が年代で違う。** 2023年は `、`、2026年は `・`。両方で分割する。
5. **比率の書式**は `10` と `10.0` が混在。数値として読む。
6. **文字コード**は UTF-8 と案内されているが、ページに文字化けの注意書きがある。`utf-8-sig` で読み、失敗したら `cp932` にフォールバックする。どちらで読めたかをログに残す。
7. **品目名の揺れ・変遷**がある。例:
   - 2023年1月に生鮮水産の上位にあった「いなだ」「白子」は、2026年8月の上位にはない。
   - 「魚卵」は 2023年1月は生鮮水産物、2026年8月は塩干・加工品その他に出る。
   - 「その他ぶり」と「その他ぶり類」は別品目。
   - 「あかいか」は生鮮・冷凍・塩干の3大品目それぞれに別行で出る。

## 5. ETL 仕様（Python）

### 5.1 構成
```
market-race/
  etl/
    fetch.py        # 一覧ページ→月ページ→CSV取得
    parse.py        # CSV→縦持ち
    normalize.py    # 名寄せ・単位処理
    build.py        # JSON 出力
    config/aliases.yml   # 名寄せ辞書（初期は空）
  data/raw/YYYYMM/       # 取得したCSVをそのまま保存（再取得を避けるキャッシュ）
  data/processed/items.csv
  data/processed/origins.csv
  web/                   # フロントエンド
  tests/
```
依存: `requests`, `beautifulsoup4`, `lxml`, `pandas`, `pytest`。

### 5.2 取得ルール
- 1秒以上の間隔を空け、User-Agent にツール名を入れる。取得済みの月は再取得しない（`--force` で上書き）。
- 一覧の全リンクを辿り、各月ページで「各種データ」の部門見出しとリンク文言から品目順位表・産地順位表のURLを決める。
- 取得結果のレポートを出力する: 月数、欠損月、部門ごとの開始月（特に花き部）、読み込みに使った文字コード。

### 5.3 縦持ちスキーマ（`items.csv` / `origins.csv`）
| 列 | 内容 |
|---|---|
| `year_month` | `YYYY-MM`（CSVの年・月列から作る） |
| `division` | `R`/`T`/`V` |
| `category` | 大品目 |
| `name` | 品目名（または原産地）。表示用は元の表記 |
| `key` | NFKC正規化＋空白除去したキー（照合用） |
| `rank` | 順位（1〜20） |
| `qty` | 数量 |
| `qty_unit` | `kg` / `本/鉢` |
| `qty_ratio` | 数量比率（％） |
| `amt` | 金額（円） |
| `amt_ratio` | 金額比率（％） |
| `related` | 主要産地（または主要品目）をリスト化したもの |
| `source_url` | 取得元CSVのURL |

「その他」行は `others.csv`（`year_month, category, kind, qty, amt, qty_ratio, amt_ratio`）に別保存する。

### 5.4 名寄せ
- キーは `(category, NFKC(name))`。表示名は最新月の表記を使う。
- 意味が違いそうな名前（いなだ／ぶり、その他ぶり／その他ぶり類など）は自動で統合しない。`aliases.yml` に統合ルールを書ける仕組みだけ用意し、統合候補は一覧で出力して人が決める。
- NFKC 後に同じキーになる表記ゆれ（全角半角、例:「ＳＰキク」）は自動で統合する。

### 5.5 出力 JSON（`web/public/data/market.json`）
```json
{
  "meta": {
    "generated": "2026-10-15",
    "months": ["2023-01", "..."],
    "categories": [{"name": "生鮮水産物", "division": "T", "qty_unit": "kg"}]
  },
  "items": {
    "生鮮水産物": {
      "まぐろ": {"qty": [59463, null, 85968], "amt": [156167808, null, 299078069],
                 "origins": [["台湾","静岡"], null, ["台湾","長崎"]]}
    }
  },
  "origins": { "生鮮水産物": { "青森": {"qty": [], "amt": [], "items": []} } }
}
```
- 配列は `months` と同じ長さ。**TOP20圏外の月は `null`**（0ではない）。

## 6. フロントエンド仕様

### 6.1 技術
Vite + TypeScript + Apache ECharts 5。サーバーなしの静的サイト。データは `market.json` を fetch する。

### 6.2 バーチャートレース（ECharts）
ECharts 公式の Bar Race 例に従う。要点:
- 棒グラフ系列に `realtimeSort: true`、`label.valueAnimation: true`
- Y軸はカテゴリ軸（`inverse: true`、表示件数 `N` に合わせて `max: N-1`）、X軸は `max: 'dataMax'`
- `animationDuration: 0`、`animationDurationUpdate` と `animationEasing(Update): 'linear'` を再生速度に合わせて設定
- 月を進めるたびに `setOption` でその月のデータを与える。コマ間の補間は ECharts のアニメーションに任せ、自前の補間は書かない
- 各大品目で「期間中に一度でも TOP20 に入った項目」の全集合をカテゴリに持つ。その月に `null` の項目は値0で渡す。表示件数は既定10件（切り替えで20件）なので、TOP20 圏外の項目が棒として現れることは通常ない。20件表示で圏外から入ってくる場合は、0から伸びるため実際の値の変化より大きく見えることを注記する
- 項目ごとの色は固定（名前のハッシュからパレットを決める）。入れ替わっても同じ品目は同じ色

### 6.3 コントロールと表示
- 大品目の選択（7種: 生鮮水産物／冷凍水産物／塩干・加工品その他／野菜／果実／切花類／鉢物類）
- 軸の切り替え: 品目／産地
- 指標の切り替え: **数量（既定）**／金額
  - 金額を選んだ場合は「数量上位20位の中での金額順」である旨を画面に常時表示する。元データの上位20位は数量で選ばれているため、金額が大きくても数量が少ない品目は含まれない可能性がある
- 花き部（切花類・鉢物類）の数量の単位は `本/鉢`。軸ラベルに単位を出す
- 再生／一時停止、月スライダー、速度（0.5x/1x/2x）、最初から再生し直すボタン
- 現在の年月を画面隅に大きく表示
- 既定の初期表示: 生鮮水産物・数量・品目・TOP10・自動再生はしない（再生ボタンで開始）
- ツールチップ: 項目名、数量、金額、主要産地（または主要品目）、前月の順位

### 6.4 自動キャプション
月が進むたびにデータから判定して、画面上部に最大2件まで表示する（優先順: 1位交代 > 急増 > TOP10新規入り）。
- 1位交代: 前月の1位と名前が違う →「◯◯が1位に（前月は△△）」
- 急増: 前月・今月とも値があり、今月が前月の3倍以上 →「◯◯が急増（前月比 x.x倍）」
- TOP10新規入り: 前月はTOP10外（圏外を含む）→「◯◯がTOP10入り」
- 最初の月は判定しない。

### 6.5 モバイル
- 縦画面で使える。ラベルフォントは14px以上、タップしやすい大きなボタン
- 項目名が長い場合は省略表示（ツールチップで全文）

## 7. 品質・検証

### 7.1 自動チェック（ETL のテストとして実装）
1. 各（月 × 大品目）で、順位1〜20が各1行、「その他」が1行
2. 数量比率の合計（20品目＋その他）が約100%（丸め誤差±0.5）
3. 取得月数が一覧のリンク数と一致
4. 全行で `qty`・`amt` が数値として読める
5. 取得した月の `year_month` が一覧の月と一致（URL由来の年月は使わない）

## 9. 運用（月次更新）
- 公開先の既定: GitHub Pages。
- GitHub Actions で毎月20日頃に実行し、未取得の月だけ取得・整形・ビルド・デプロイする。新しい月が無ければ何もしない。
- 取得に失敗した月（リンク構造の変更など）は、ジョブを失敗させて通知する。

## 10. 実装フェーズ
1. **P0 取得と調査**: 全44か月の取得、レポート出力（花き部の開始月、文字コード、リンク構造の例外）。
2. **P1 ETL**: 縦持ち生成、テスト（7章）、`market.json` 出力。
3. **P2 フロントMVP**: バーチャートレース、コントロール、スマホ表示。
4. **P3 演出**: キャプション、色、ツールチップ、金額モードの注記。
5. **P4 公開と自動更新**: クレジット、デプロイ、月次ジョブ。
6. **P5（任意）**: バンプチャート、単価の遷移、D3 への移行判断。

## 11. 既知の制約・リスク
- **期間が短い。** 月次データは 2023年1月から。「昔から」といっても約3年8か月。
- **上位20位のみ。** 圏外の値は不明。
- **金額順は不完全。** 上位20位が数量順で選ばれているため（4.4-2）。
- **名称の変遷。** 品目の入れ替わりや分類の移動があり、時系列が途切れる項目がある（4.4-7）。
- **ページ構造の変更リスク。** リンク構造・ファイル名は年代で変わっている。取得ロジックはリンク文言と見出しに依存するため、変更時に壊れる可能性がある。
- **花き部の開始月が未確認。**
- **2023年1月と2026年8月以外の月は中身を未確認。** 途中の月で列名や構造が変わっていないかは P0 で確認する。

## 12. 受け入れ基準
- P0 のレポートで44か月分すべて取得でき、例外があれば一覧化されている
- 7.1 の自動チェックがすべて通り、7.2 のフィクスチャと一致する
- スマホ（縦画面）で、生鮮水産物・数量・TOP10のレースが最初から最後まで再生できる
- 大品目・軸・指標を切り替えても再生が崩れない
- 金額モードの注記とクレジットが常に表示されている
- 新しい月が公開されたとき、手作業なしで反映される
